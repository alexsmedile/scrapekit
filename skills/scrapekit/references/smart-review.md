# smart-review — scraping failure analysis

Triggered when the user asks for a "smart review", "review failures", "what went wrong", or similar.

## Process

### 1. Read the session log

```bash
cat .scrapekit/session.log 2>/dev/null || echo "No session log found."
```

Filter for failures only:

```bash
grep -E '^[^\t]+\t(err|thin)\t' .scrapekit/session.log 2>/dev/null
```

### 2. Cross-reference with chat history

For each `err` or `thin` entry in the log, check whether the current chat history contains context about that URL or tool call (error messages, tool output snippets, escalation attempts).

- If chat context exists → confidence: **high**
- If log entry only, no chat context → confidence: **low** (flag as "no context available — log entry only")

### 3. Produce structured report

One block per failure:

```
────────────────────────────────────────
Target:      <URL or command>
Tool:        <tool name>
Status:      err | thin
Timestamp:   <from log>
Confidence:  high | low

Hypothesis:
  <What likely went wrong — bot block, paywall, wrong tool for content type,
   missing API key, thin SSR page, JS-rendered content, etc.>

Suggested fix:
  <Specific routing change, escalation rule, or new exception to add to SKILL.md.
   Be concrete: "add X to escalation chain before Y" or "route domain Z directly to apify".>
────────────────────────────────────────
```

After all failure blocks, add a **Summary** section:

```
## Summary

Failures reviewed: N
High confidence:   N
Low confidence:    N

Patterns:
  <Group repeated root causes. e.g. "3 bot-blocks on news sites — escalate to
   jina earlier" or "2 thin results from trafilatura on SPAs — route to webclaw first".>

Suggested SKILL.md changes:
  <Consolidated list of routing rule changes, deduped across individual failures.>
```

### 4. Ask the user what to do with the report

After presenting the report, ask:

> **What would you like to do with this?**
> 1. **Save locally** — write report to `.scrapekit/review-YYYY-MM-DD.md` for a fix-later workflow
> 2. **Open GitHub issue** — pre-fill and submit to `alexsmedile/scrapekit` via `gh issue create`
> 3. **Both**
> 4. **Nothing** — report only, no action

#### Save locally

Write to `.scrapekit/review-YYYY-MM-DD.md` (use today's date). Tell the user:
> "Saved to `.scrapekit/review-YYYY-MM-DD.md`. When you're ready to apply fixes, say 'apply smart review' and I'll patch your local SKILL.md."

#### Open GitHub issue

Format the issue as:

**Title:** `scraping failures — <date> — <N> items`

**Body:**
```markdown
## Failures

<paste the structured failure blocks>

## Suggested fixes

<paste the consolidated SKILL.md changes from Summary>

---
*Generated by scrapekit smart-review*
```

Run:
```bash
gh issue create \
  --repo alexsmedile/scrapekit \
  --title "scraping failures — <date> — <N> items" \
  --body "$(cat <<'EOF'
<body>
EOF
)"
```

Print the issue URL after creation.

## Notes

- Low-confidence entries (log only, no chat context) should still be included but clearly marked — they may still reveal patterns worth fixing even without full context.
- If the session log is empty or has no failures, say so and exit: "No failures recorded in `.scrapekit/session.log` for this session."
- If `.scrapekit/session.log` does not exist, say: "No session log found — make sure the PostToolUse hook is active. See `references/setup.md`."
- Do not attempt to apply SKILL.md patches automatically during this flow — only report and ask. Applying is a separate action the user initiates.
